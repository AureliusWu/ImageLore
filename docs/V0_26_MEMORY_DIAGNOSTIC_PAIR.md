## 测量口径与实际结果

每组目标活动时长 600,000 ms，300 步操作，步间隔 2,000 ms；启动后稳定等待 20,000 ms，进程树内存目标采样间隔 10,000 ms。活动区间内各有 60 次采样，操作、运行时和控制台错误均为 0。统计使用该组活动开始前的 baseline；每组 3 次准备阶段采样及 6 次被动尾段采样排除在活动区间结果之外。

| 指标 | 初始条目反复滚动 `repeated-scroll` | 不同图片加载 `thumbnail-scroll` |
| --- | ---: | ---: |
| 实际活动时长 | 600,008 ms | 600,009 ms |
| 操作数 / 活动采样数 | 300 / 60 | 300 / 60 |

两个窗口观察到的峰值和活动末值均严格低于相对 baseline 的 20% 预算。第一组后半段 30 个采样点的 Private Bytes 趋势仍为正，因此保留 `WARN`；末值低于 baseline 不能取消该趋势警告。第二组只在本次活动窗口获得 `PASS_THIS_WINDOW`，不证明长期运行稳定。

baseline 与活动内第一个采样点不是同一时间点。第一组 baseline 在活动开始前 942 ms，首个活动点晚 9,134 ms，最后活动点距结束 1,014 ms；第二组分别为 655 / 9,507 / 570 ms。表中的“活动末值”指最后一个活动区间内采样点，未使用 60 秒被动尾段替换，也未把启动/准备阶段纳入活动峰值。

这些峰值仅是采样点观察到的最大值。最大相邻采样间隔由独立复核基于原始活动点时间戳派生，并非 runner 直接给出的字段。最大约 11.4 秒的间隔可能漏掉瞬时峰值，活动起点与终点也存在上述采样偏移。进程树 Working Set 合计可能重复计算共享页，不能直接当成系统唯一物理内存占用；Private Bytes 与 Working Set 保留各自口径。

两组均通过 OS `WM_CLOSE` 正常关闭，保留进程句柄读取到确切退出码 `0`，调试端口已释放；未强制终止。整个串行诊断正常完成于 `2026-10-09T15:38:29.013Z`（北京时间 23:38:29.013）。正常退出与端口释放证明本次运行的收尾完成，不替代完整关闭、备份或恢复故障矩阵。

## 与既有警告的关系

旧 `cd220b2` 产物的[五组内存隔离窗口](V0_26_MEMORY_ISOLATION.md)保持原结论：连续换图末 Private Bytes `+23.91%`、仅缩略图滚动 `+29.36%`，两项仍超 20% 预算；固定小图的未知子进程采样缺口亦保留。本轮来源是 `ec8874f`，只有上述两组诊断；场景及产物身份不能替代旧版与新版的同条件配对，因此不能据此将旧 `WARN` 标为已修复。

目前没有实际测量证明缩略图分辨率造成过量解码或 GPU 占用，也未证明内存泄漏。本轮不据此修改 `LazyThumb` 的 `420px` 请求或显示质量。现有图片使用 `object-fit: cover`；后续若有证据需要调整，请求尺寸必须考虑容器宽高、图片比例、DPR 和 resize，窄长图片的 cover 裁切可能需要更长边。后端仍先完整解码原图，减小输出边长本身不能证明原图解码峰值下降，小图也不会被缩小为请求上限。
