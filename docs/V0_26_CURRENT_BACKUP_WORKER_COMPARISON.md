## 可比条件与数据保全

四次使用相同的原始 DB/WAL/SHM 与十份备份，十三文件的完整清单、字节数、SHA256、mtime 和操作顺序逐项相同；分别准备全新副本。四次均为 50,000 资产、初始与最终各十份有效备份、相同 clone-only checkpoint 方法和 32768 KiB validator cache。准备、复制、hash 和未计时断言会预热缓存，这不是冷启动测试。两个程序均为实际归档的优化 lib test，没有构建应用安装包。

四次均执行 typed 业务快照、真实备份/暂存/应用恢复、关闭连接再重开、修改前状态恢复和原件 raw 保全。原始源只用独占只读句柄持有，未由 SQLite 打开；最终源保全回执确认十三文件前后不变。没有打开正常用户资料库。

新报告逐 session 核对完整 validator 的七个阶段及 SQL 结果；B1/B2 每次轮换 worker 数均依次为 `0 / 0 / 11 / 11 / 0 / 10`。两路实现每批最多两个 worker，trace 中的 join-before-consumption 仍为未记录，其顺序由同源实现及完整回归中的七项轮换测试验证。串行报告遗漏的直接 guarded validator 总数不能记为零，也不与新报告计数作差推断跳过检查；父子 span 和不同 worker 的时间不能重复求和。两路测试观测增加完整 guarded scopes 和 SQL 结果标记，本轮未独立隔离其开销。

独立只读比较脚本另外核对四套执行输入和源快照、优化构建身份、68 项实际完整回归输入、十六份成功终态与原始 stdout、六操作 root 及报告 SHA、四份十三源文件清单完全相同、实际测试不重叠且顺序为 A1/B1/B2/A2。两组源输入只差 `backup.rs` 和 `backup/guarded_restore.rs`；同方案两个样本的程序归档和执行脚本字节完全相同。比较回执没有将本轮计入正式冷暖样本。
