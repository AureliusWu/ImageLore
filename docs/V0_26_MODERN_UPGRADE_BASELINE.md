# 独立数据目录的 Windows 升级验收准备

记录日期：2026-10-26；版本保持 `0.26.0`。本批扩展升级测试，不改变产品代码、schema 或桌面 current；新的双基线托管安装结果尚待取得。

## 两个固定基线

原有 Windows 工作流只构建并安装 `0.19.0`，其 schema 7 数据位于安装目录。它验证旧目录迁移，不能直接证明已经使用独立数据目录的 `0.25.1` 用户如何升级。

新增基线取自公开、清理后的固定历史：

| 版本 | 源码提交 | 实际 schema | 初始数据目录 |
| --- | --- | ---: | --- |
| 0.19.0 | `cfe80c5dfa6e4290b6372910e2a98908193e0b13` | 7 | 安装目录 |
| 0.25.1 | `202dee3a6b5c3746bbad5e4c7f58e0e2e0875ef3` | 11 | `app.imagelore.desktop` |

两个基线各自在新建的 runner 临时 worktree 中构建；核对固定 HEAD 与 VERSION 后记录实际 NSIS 和 schema 路径。当前应用只构建一次，再依次执行两条安装路径，任一路径失败都阻止上传/Release。脚本仍首先拒绝本机或 self-hosted 执行，没有临时放宽托管条件。

## 数据与原件核对

`0.19.0` 保留原有七表哨兵。`0.25.1` 从其实际 schema 创建 **23 张非空业务/设置表**：包括两张图片记录、编辑历史、标签/集合/谱系、Visual DNA、生成参数索引、512 维语义向量、模型设置、生成会话、别名、筛选器、待解析谱系、资料源、Vision 设置/分析、Remix 和来源信息。每行的全部列都进入快照，向量 BLOB 按完整十六进制字节比较。

资料源自动同步关闭，语义设置保持禁用，Vision endpoint 使用保留的合成域名；夹具不请求外部分析。向量是合成哨兵，不是模型推理结果。FTS 内部派生表不计入 23 张业务/设置表。

安装后的两次启动都须核对内层 EXE 与当前构建输出的完整哈希、实际旁置 DLL 加载、正常关闭，以及只读数据库的 schema/完整性/外键和所有哨兵。合成原图的大小/完整 SHA-256、备份及模型哨兵字节也须保持。`0.25.1` 路径直接保留已有独立数据目录；不能为了测试强行把它改放回安装目录。

## 已执行的组件检查与边界

本地只执行新建隔离目录内的 Python/SQLite 组件检查，**13 案通过**：真实两个历史 schema 的建库/快照、现代 23 表与向量原字节正常回读、旧 schema 在 Native 迁移前拒绝，以及标签/向量/设置/原图篡改、未来 schema、空或未知快照、既有夹具覆盖和 schema pin 不符的拒绝。

两种版本参数的本机调用都实际在接触用户路径之前拒绝；PowerShell 脚本与解析后工作流代码块 AST、步骤顺序、手动上传默认关闭和项目检查通过。首次 12 案与追加原图字节检查后的 13 案分别保留，没有把旧 schema marker 手动改成 11 来声称 Native 迁移通过。

这些结果只证明夹具与只读断言可用。本机没有安装/启动基线或候选；真正的双基线覆盖安装、四次正常关闭与完整回读仍须由新源码托管运行取得。它也不代替用户机器 GUI、真实模型、正式性能、签名、updater 或 RC 验收。
